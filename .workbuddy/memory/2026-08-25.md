# 2026-08-25

## 单文件夹打包 + 修复 UI 不显示（致命 bug）

- 将 PyInstaller 由单文件改为**单文件夹（onedir）**：spec 中 `EXE` 加 `exclude_binaries=True`，新增 `coll = COLLECT(...)`，输出 `release/DTUG-IDE/`（exe + `_internal/` + DLL + ico）。
- `tools/make_release.py` 改为复制整个 `release/DTUG-IDE/` 文件夹进发布包（原先只复制单个 exe）。
- onedir 模式下数据文件落在 `release/DTUG-IDE/_internal/`，故 `utils.find_app_icon()` 增加 `base/_internal/dtug-ide.ico` 候选路径；`__main__` 增加 `_ensure_qt_plugin_path()` 显式把打包的 Qt 插件目录加入搜索路径（兜底防平台插件找不到）。
- `__main__.py` / `编译.py` 增加「崩溃写日志」：`sys.excepthook` + try/except 把异常写入 exe 同目录 `DTUG_IDE_crash.log`，便于窗口程序静默崩溃时排查。

### 根因：编辑器语法高亮器崩溃导致窗口起不来
- 现象：双击 exe 有进程但 UI 从不显示，几秒后退出。offscreen 冒烟测试（跳过 qwindows 原生层）误报“正常”，掩盖了问题。
- 真因：`dtug_ide/editor.py` 的 `CppHighlighter.highlightBlock` 中所有
  `for match in X.globalMatch(text):` 在 **PyQt6 下均报错**
  `TypeError: 'QRegularExpressionMatchIterator' object is not iterable`。
  `QRegularExpression.globalMatch()` 返回迭代器，必须用 `while it.hasNext(): it.next()`。
  该异常在真实 Windows 渲染每一行时于 paint 过程中抛出，直接让窗口无法显示。
- 修复：新增模块级辅助 `_iter_matches(iterator)`（while hasNext/next），把 8 处循环全部改为
  `for match in _iter_matches(X.globalMatch(text)):`。
- 验证：`highlightBlock` 对含 `//`、关键字、字符串、多行注释的样例全部通过；`CodeEditor` 构造并 `processEvents()` 无异常；重建 exe 后 offscreen 跑 6s **不再生成 `DTUG_IDE_crash.log`**。

### 备注
- 沙箱安全删除 shim 会拦截 >50 文件的 `rm`（回收站不可用），且 PyInstaller `--noconfirm` 清理旧 `build/` 时也会触发而中止构建。 workaround：先把旧目录 `mv` 重命名，再用全新 `--workpath build_new` 构建（不触发删除）。旧目录暂存 `_trash/`。
- 构建后 `dtug_ide.egg-info/` 会出现（build 产物），未被 make_release 打包，可忽略。
